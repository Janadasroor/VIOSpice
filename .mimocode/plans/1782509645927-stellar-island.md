# Plan: GUI Remote Control via CLI

## Goal
Add a `viora gui` CLI subcommand that controls the running VioSpice GUI — enumerate buttons, click them, type in fields, trigger menu actions. Fully dynamic, no hardcoding.

## New Files

### 1. `ui/gui_manager.h` + `ui/gui_manager.cpp`

Singleton `GuiManager` with:

```cpp
class GuiManager : public QObject {
    Q_OBJECT
public:
    static GuiManager& instance();

    struct ElementInfo {
        QString type;       // QPushButton, QToolButton, QAction, QLineEdit, QTextEdit
        QString label;      // button text / action text / placeholder
        QString objectName;
        QRect geometry;     // global coords
        bool enabled;
        QString parentName; // toolbar objectName or "MenuBar"
    };

    QVariantList listElements(const QString& windowName,
                              const QString& filterType = "",
                              const QString& filterParent = "") const;
    QVariantMap clickButton(const QString& windowName, const QString& target);
    QVariantMap typeInField(const QString& windowName, const QString& objectName,
                            const QString& text, bool append = false);
    QVariantMap triggerMenuAction(const QString& windowName, const QString& actionText);

private:
    explicit GuiManager(QObject* parent = nullptr);
    QWidget* findWindow(const QString& name) const;
    QWidget* findChildByLabel(QWidget* parent, const QString& label) const;
    QAction* findActionByText(QWidget* window, const QString& text) const;
    static bool fuzzyMatch(const QString& candidate, const QString& query);
};
```

**Core mechanism:**
- Window lookup: reuse `QApplication::topLevelWidgets()` + className/windowTitle/objectName matching (same pattern as ScreenshotManager)
- Element discovery: `window->findChildren<QPushButton*>()`, `findChildren<QToolButton*>()`, `menuBar()->findChildren<QAction*>()`, `findChildren<QLineEdit*>()`
- Click: construct `QMouseEvent(QEvent::MouseButtonPress/Release, localPos, globalPos, Qt::LeftButton, Qt::LeftButton, Qt::NoModifier)` → `widget->event(&event)` (follows existing pattern in `schematic_view.cpp:1301`)
- Menu trigger: walk `menuBar()->findChildren<QMenu*>()` → match action `text()` → `action->trigger()`
- Type: `lineEdit->setText()` or `lineEdit->insert()` for append

## Modified Files

### 2. `ui/app_command_server.cpp` — Add 4 commands

Add `else if` branches after `screenshot_children`:

- **`gui_list_elements`**: `{window, type?, parent?}` → `{elements: [{type, label, objectName, x, y, w, h, enabled, parentName}]}`
- **`gui_click`**: `{window, target}` → `{clicked, type, label}`
- **`gui_type`**: `{window, target, text, append?}` → `{typed}`
- **`gui_menu`**: `{window, action}` → `{triggered}`

### 3. `cmake/project_sources.cmake` — Add source files

### 4. `cli/main.cpp` — Add `gui` subcommand

```
viora gui list-buttons [--window <name>] [--type <QToolButton|QPushButton|QAction>] [--parent <toolbar>]
viora gui click <label-or-name> [--window <name>]
viora gui type <field-name> <text> [--window <name>] [--append]
viora gui menu <action-text> [--window <name>]
```

All use existing `sendWebSocketCommand()` helper.

## Data Flow

```
CLI: viora gui click "Run Simulation" --window SchematicEditor
  → WebSocket → UICommandServer
  → gui_click handler → GuiManager::clickButton("SchematicEditor", "Run Simulation")
  → findWindow() → findActionByText() → action->trigger()
  → JSON response back to CLI
```
