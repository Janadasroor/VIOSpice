# Extension IDE Module — Implementation Plan

## Overview

Create a new standalone `extension_ide/` module: a full-featured QMainWindow IDE for editing FluxScript extensions (.flux files and manifest.json). The existing ScriptEditorTab in `schematic/ui/` stays untouched for quick inline edits.

---

## Directory Structure

```
extension_ide/
├── CMakeLists.txt                    # Static library: VioExtensionIDE
├── extension_ide_window.h/.cpp       # Main QMainWindow (the IDE window)
├── editor/
│   ├── ide_editor.h/.cpp             # Enhanced FluxScript code editor (extends Flux::CodeEditor)
│   ├── ide_highlighter.h/.cpp        # Extended FluxScript syntax highlighter
│   ├── ide_completer.h/.cpp          # Enhanced code completer (API, math, keywords)

│   └── ide_find_replace.h/.cpp       # Enhanced find & replace bar

│   ├── api_reference_panel.h/.cpp    # Right dock: browseable API reference
│   ├── output_panel.h/.cpp           # Bottom dock: console output / terminal
│   ├── manifest_editor_panel.h/.cpp  # Integrated manifest.json visual editor
│   ├── template_browser_panel.h/.cpp # Dock: template/example browser
│   └── extension_scaffold_dialog.h/.cpp  # New Extension wizard
├── core/
│   ├── extension_runner.h/.cpp       # Run/stop extensions via FluxScriptEngine

```

```
└── IdeFindReplace (find bar)

└── Uses FluxScriptEngine singleton

```

## Phase-by-Phase Implementation

### Phase 1: Skeleton + Enhanced Editor (foundation)
**Files**: CMakeLists.txt, extension_ide_window, ide_editor, ide_highlighter, ide_completer, ide_tab_widget, ide_find_replace

1. Create `extension_ide/CMakeLists.txt` with VioExtensionIDE static library
2. Add to root `CMakeLists.txt` (add_subdirectory) and `cmake/project_sources.cmake`
3. Implement `ExtensionIdeWindow` — empty QMainWindow with menu bar, toolbar, status bar
4. Implement `IdeEditor` extending `Flux::CodeEditor`:
   - Line number gutter via custom `paintEvent` override
   - Bracket matching (highlight matching pair, auto-pair on type)
   - Auto-indent (indent on Enter, dedent on `}`)
   - Code folding (fold `def` blocks, fold markers in gutter)
   - Current line highlight
5. Implement `IdeHighlighter` extending `FluxHighlighter`:
   - Add JSON highlighting rules for manifest.json files
   - Add block folding regions for `def`/`struct`/`class` blocks
6. Implement `IdeCompleter` extending `FluxCompleter`:
   - Add all FluxScript bridge API function names
   - Add math built-ins
   - Add FluxScript keywords (adevice, etc.)
   - Group items by category in completion popup
7. Implement `IdeTabWidget` — QTabWidget with:
   - Tab context menu (Close, Close Others, Close All, Copy Path)
   - Modified indicator (*)
   - Tab drag reordering
   - Reopen closed tab (Ctrl+Shift+T)
8. Implement `IdeFindReplace` — inline toolbar-style find bar:
   - Find/replace/all, regex toggle, case sensitive, match count
   - Replaces the current modal dialog approach

### Phase 2: IDE Layout + Docks
**Files**: file_tree_panel, api_reference_panel, output_panel, api_reference_data

1. Implement `FileTreePanel`:
   - QTreeView + QFileSystemModel filtered to extension directory
   - Context menu: New File, New Folder, Rename, Delete, Open
   - Double-click opens file in editor
   - Git status badges (if available)
2. Implement `ApiReferencePanel`:
   - Searchable QListView of all bridge functions
   - Function signature + description display
   - Click to insert function name at cursor
   - Categories: Qt Widgets, Workspace, Simulation, Math
3. Implement `ApiReferenceData`:
   - Static data structure with all `flux_qt_*`, `flux_*`, `viora_*` functions
   - Extracted from `flux_qt_bridge.cpp`, `flux_workspace_bridge.cpp`, `flux_design_rule_bridge.cpp`
4. Implement `OutputPanel`:
   - Colored QTextEdit (errors in red, stdout in white, JIT status in cyan)
   - Click on error line → navigate to that line in editor
   - Clear button, auto-scroll toggle
5. Wire all docks into `ExtensionIdeWindow`:
   - Left: FileTree
   - Right: ApiReference (tabbed with Templates in Phase 3)
   - Bottom: Output
   - Corner rules to prevent dock stretching
   - View menu toggles

### Phase 3: Extension Tools
**Files**: manifest_editor_panel, template_browser_panel, extension_scaffold_dialog

1. Implement `ManifestEditorPanel` (as dock widget, not modal dialog):
   - Form fields: ID, Name, Version, Author, Main File, Description
   - Menu entries list (add/remove/edit path + action)
   - Context handlers list (add/remove/edit componentType + action)
   - Live JSON preview pane
   - Validation: required fields, function names exist in main .flux
   - Auto-save or Save button
2. Implement `TemplateBrowserPanel`:
   - Read from `python/templates/`, `python/automation/`, `examples/`
   - Category sidebar: ALL, SIMULATION, AUTOMATION, EXAMPLES
   - Search bar
   - Click to open template in editor
   - Preview on hover/select
3. Implement `ExtensionScaffoldDialog`:
   - Multi-step wizard: Name → Template → Confirm
   - Templates: Empty, Panel, Calculator, Dashboard
   - Creates directory + manifest.json + main.flux
   - Opens created files in editor

### Phase 4: Run & Debug
**Files**: extension_runner

1. Implement `ExtensionRunner`:
   - `run(source)` — calls FluxScriptEngine::finalize() + initialize() + executeString()
   - Captures stdout via JITContextManager signals
   - Parses error messages for line/column info
   - Emits signals: outputReceived, errorOccurred, runStarted, runFinished
2. Wire run/stop buttons in toolbar
3. Error line highlighting in editor (reuse IdeEditor's error lines)
4. Click error in output panel → navigate to line
5. Step/Resume/Stop debugger integration with `Debugger` singleton
6. Hot-reload indicator: watch extension directory, notify on changes

### Phase 5: Integration
**Files**: project_manager modifications, main.cpp, session state

1. Implement `ExtensionIdeState`:
   - Save/restore open files list, window geometry, dock states
   - Persist to ConfigManager
2. Add to ProjectManager:
   - New launcher tile: "Extension IDE" with description
   - `openExtensionIde()` slot creates new `ExtensionIdeWindow`
   - `openExtensionIde(filePath)` opens with specific file
3. Route .flux double-click in ProjectManager to Extension IDE
4. Add to main.cpp session restore: remember if ExtensionIdeWindow was open
5. CLI: `viora extension open <dir>` launches IDE with directory

## Migration Strategy

**Enhance, don't rewrite.** The new `IdeEditor` extends `Flux::CodeEditor` — it inherits the existing 471 lines of working code (highlighter, completer, find/replace, error highlighting, tooltips, run execution). We add line numbers, bracket matching, auto-indent, and code folding on top.

`IdeHighlighter` extends `FluxHighlighter` — inherits all existing rules, adds JSON rules and folding regions.

`IdeCompleter` extends `FluxCompleter` — inherits component type + library symbol completion, adds API function names and math built-ins.

The existing `Flux::ScriptEditorTab` in `schematic/ui/` is **not modified or removed** — it continues to work for quick inline editing within the schematic editor.

## CMake Integration

### New `extension_ide/CMakeLists.txt`
```cmake
qt_add_library(VioExtensionIDE STATIC ${EXTENSION_IDE_SOURCES})
target_include_directories(VioExtensionIDE PUBLIC ${CMAKE_CURRENT_SOURCE_DIR})
target_link_libraries(VioExtensionIDE PUBLIC VioCore Qt6::Widgets Qt6::Svg)
# Links FluxScript headers from core/flux/
```

### Root `CMakeLists.txt` additions
```cmake
add_subdirectory(extension_ide)
# In target_link_libraries for VioraEDA: add VioExtensionIDE
```

### `cmake/project_sources.cmake` addition
```cmake
# =============================================================================
# EXTENSION IDE MODULE - Full IDE for FluxScript extension development
# =============================================================================
set(EXTENSION_IDE_SOURCES
    extension_ide/extension_ide_window.cpp
    extension_ide/extension_ide_window.h
    # ... all files listed above
)
```

## Key Design Decisions

1. **Extends, not copies**: IdeEditor inherits Flux::CodeEditor — no code duplication
2. **Standalone window**: Not embedded in schematic, independent lifecycle
3. **Dock-based layout**: Follows Symbol Editor pattern (left/right/bottom docks)
4. **Manifest editor as panel**: Not a modal dialog — live editing with JSON preview
5. **File tree scoped to extension dir**: Not a general file browser — focused on the active extension
6. **API reference as data**: Static data from bridge source files, not runtime introspection
7. **Keep ScriptEditorTab**: No breaking changes to schematic editor workflow
