# VioraIDE: LSP Integration + UX Test Automation — Implementation Plan

## Overview

Three deliverables:
1. **Full LSP client** for VioraIDE — connect to the FluxScript `flux-lsp` server (stdio JSON-RPC 3.17) for real-time completions, diagnostics, hover, go-to-definition, and references.
2. **Enhanced UX test scripts** — comprehensive UI/UX automation tests with screenshots for every panel, feature, and interaction.
3. **Build discipline** — always use `-j8`.

---

## Part 1: LSP Client for VioraIDE

### Architecture

```
VioraIdeWindow
  └── LspClient (QObject, lives in viora_ide/core/)
        ├── QProcess → flux-lsp --stdio
        ├── stdio JSON-RPC transport (Content-Length headers)
        ├── Document sync (open/change/close/save)
        └── Signals: diagnosticsReceived, completionsReady, hoverReady, ...

  └── IdeEditor
        ├── On text change → debounced didChange (300ms)
        ├── On open file → didOpen
        ├── On save → didSave
        └── On close → didClose
```

The FluxScript LSP server (`flux-lsp`) is already built at `/usr/local/bin/flux-lsp`. It communicates via stdio with `Content-Length` header framing (standard LSP). We build a Qt `QProcess`-based client that speaks JSON-RPC over stdio.

### LspClient Design

```
class LspClient : public QObject {
    Q_OBJECT
public:
    explicit LspClient(QObject* parent = nullptr);
    ~LspClient();

    bool startServer(const QString& serverPath = "flux-lsp");
    void stopServer();
    bool isRunning() const;

    // Document lifecycle
    void openDocument(const QString& filePath, const QString& text);
    void changeDocument(const QString& filePath, const QString& text, int version);
    void closeDocument(const QString& filePath);
    void saveDocument(const QString& filePath);

    // Requests (async, emit signal on response)
    void requestCompletions(const QString& filePath, int line, int character);
    void requestHover(const QString& filePath, int line, int character);
    void requestDefinition(const QString& filePath, int line, int character);
    void requestReferences(const QString& filePath, int line, int character);
    void requestDocumentSymbol(const QString& filePath);
    void requestSignatureHelp(const QString& filePath, int line, int character);
    void requestFormatting(const QString& filePath);

signals:
    void serverStarted();
    void serverStopped();
    void diagnosticsReceived(const QString& filePath, const QList<LspDiagnostic>& diagnostics);
    void completionsReady(int requestId, const QList<LspCompletionItem>& items);
    void hoverReady(const QString& contents, const QString& filePath, int line, int col);
    void definitionReady(const QString& filePath, int line, int character);
    void referencesReady(const QList<LspLocation>& locations);
    void documentSymbolReady(const QList<LspSymbol>& symbols);
    void signatureHelpReady(const QList<LspSignature>& signatures);
    void formattingReady(const QString& newText);
    void errorOccurred(const QString& message);
};
```

### JSON-RPC Transport (stdio)

```
Client → Server (request):
  Content-Length: <N>\r\n
  \r\n
  {"jsonrpc":"2.0","id":1,"method":"textDocument/completion","params":{...}}

Server → Client (response or notification):
  Content-Length: <N>\r\n
  \r\n
  {"jsonrpc":"2.0","id":1,"result":{...}}
  {"jsonrpc":"2.0","method":"textDocument/publishDiagnostics","params":{...}}
```

Implementation:
- `QProcess` with `setReadChannel(QProcess::StandardOutput)`
- Read loop on `readyReadStandardOutput`: accumulate in `QByteArray`, split on `\r\n\r\n` header separator, parse `Content-Length`, read body
- Write: `Content-Length: <N>\r\n\r\n<JSON>` to `QProcess::write()`
- Each outgoing request gets a unique incrementing `id`. Store pending requests in `QMap<int, PendingRequest>` where `PendingRequest` holds a lambda/callback.
- Incoming `publishDiagnostics` notifications are dispatched immediately via signal.
- Incoming responses are matched by `id` and the stored callback is invoked.

### Document Sync Protocol

```
initialize:
  {"capabilities": {"textDocument": {"completion": {"completionItem": {"snippetSupport": true}},
    "hover": {"contentFormat": ["markdown", "plaintext"]},
    "definition": {}, "references": {}, "publishDiagnostics": {},
    "synchronization": {"didSave": true}}}}

textDocument/didOpen:
  {"textDocument": {"uri": "file:///...", "languageId": "flux", "version": 1, "text": "..."}}

textDocument/didChange:
  {"textDocument": {"uri": "file:///...", "version": N},
   "contentChanges": [{"text": "full text"}]}
  // Full document sync (simpler, works well for typical extension files <10k lines)

textDocument/didSave:
  {"textDocument": {"uri": "file:///..."}}
```

### IdeEditor LSP Integration

1. **Text change → didChange**: Connect `QPlainTextEdit::textChanged` to a debounce timer (300ms). When timer fires, emit `contentsChanged(filePath, toPlainText())`. VioraIdeWindow forwards to `LspClient::changeDocument()`.

2. **File open → didOpen**: When `IdeEditor::openFile()` succeeds, emit `fileOpened(filePath, toPlainText())`. Window forwards to `LspClient::openDocument()`.

3. **File save → didSave**: When `IdeEditor::saveFile()` succeeds, emit `fileSaved(filePath)`. Window forwards to `LspClient::saveDocument()`.

4. **File close → didClose**: When `IdeTabWidget::closeTab()` removes editor, emit `fileClosed(filePath)`. Window forwards to `LspClient::closeDocument()`.

5. **Diagnostics → underline squiggles**: `LspClient::diagnosticsReceived` → `IdeEditor::setErrorLines(errors)` (already exists in base `Flux::CodeEditor`). Each diagnostic's line/col/range maps to error line marks.

6. **Hover → tooltip**: `IdeEditor::mouseMoveEvent()` with Ctrl held → request hover at cursor position. Response displayed as rich tooltip (markdown rendered as HTML).

7. **Completions → popup**: Override `IdeCompleter::getCompletions()` to request from LSP instead of static list. Fall back to static list if LSP is not running.

### Problems Panel

A new `ProblemsPanel` in the bottom panel area (tabbed with Output):
- QTreeWidget with columns: Severity icon, Message, File, Line
- Click row → navigate to that diagnostic in the editor
- Auto-populates from `LspClient::diagnosticsReceived`
- Filter by severity (error/warning/info)
- "Problems (N)" tab title with count badge

## Key Design Decisions

1. **QProcess + stdio** (not TCP/socket) — matches flux-lsp's default transport, no config needed
2. **Full document sync** — simpler than incremental for typical extension files (<10k lines)
3. **300ms debounce** — balance between responsiveness and server load
4. **LSP completions replace static** — LSP has richer completions (snippets, signatures); static list is fallback only
5. **Problems as separate panel** — not embedded in output panel; cleaner separation of concerns
6. **No external LSP library** — hand-roll the JSON-RPC framing (simple protocol, ~200 lines) to avoid adding a dependency
